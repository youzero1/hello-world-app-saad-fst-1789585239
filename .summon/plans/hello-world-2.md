Project inspection: the project is currently empty (no files returned by the structure scan), so this plan covers full scaffolding of the minimum needed for one styled page.

## Phase 1 — Project scaffolding

1. Create `package.json` with ESM (`"type": "module"`) and npm scripts for dev, build, and preview. Dependencies: react, react-dom, @tanstack/react-router. Dev dependencies: vite, @vitejs/plugin-react, typescript, @types/react, @types/react-dom, @tailwindcss/vite, @tanstack/router-plugin.
   - Outcome: `npm install` succeeds and `npm run dev` is available.
2. Create `vite.config.ts` registering, in order, the TanStack Router plugin (file-based route generation from `src/routes`), the React plugin, and the Tailwind CSS v4 Vite plugin. Configure the `@/` alias to resolve to `src/`.
   - Outcome: routes auto-generate and Tailwind classes compile.
3. Create `tsconfig.json` (and `tsconfig.node.json` if needed) with strict mode, bundler module resolution, `jsx: react-jsx`, and the `@/*` → `src/*` path mapping matching the Vite alias.
   - Outcome: no TypeScript path or JSX errors.
4. Create `index.html` at the project root with a `#root` mount node, sensible `<title>` ("Hello World 2"), and a module script tag pointing at `src/main.tsx`.
   - Outcome: app shell loads in the browser.
5. Create `.gitignore` covering `node_modules`, `dist`, and local env files. Note that `src/routeTree.gen.ts` is generated by the router plugin and must never be hand-edited.
   - Outcome: generated/installed artifacts stay out of source control.

## Phase 2 — Styling and app entry

6. Create `src/styles/global.css` whose first line is exactly the Tailwind import, followed by nothing else for now.
   - Outcome: Tailwind v4 utilities available app-wide.
7. Create `src/main.tsx` that imports `@/styles/global.css` once, creates the router from the generated route tree, and renders the router provider into `#root` inside React StrictMode. Include the TanStack Router type-registration declaration.
   - Outcome: app boots with routing and styles wired up, fully typed.

## Phase 3 — Root shell and the page

8. Create `src/routes/__root.tsx` as the app shell: a root route rendering an `Outlet` inside a full-height wrapper with a light background (soft near-white), default text color (dark slate), and antialiased text. No header, nav, or footer — the app is intentionally single-page.
   - Outcome: every route renders inside a clean, light, full-viewport shell.
9. Create `src/routes/index.tsx` as the `/` route. Content: a centered vertical stack — a large heading reading "Hello World", and one short muted subtitle line beneath it. Use flex centering on the full viewport height, generous padding, constrained max width, and responsive type scale (smaller heading on mobile, larger on `sm`/`md` and up). Optional subtle touches only: tight letter-spacing on the heading and a thin divider or small accent dot above it.
   - Outcome: visiting `/` shows a nicely typeset, vertically and horizontally centered greeting.

## Acceptance criteria

10. `npm run dev` starts with no TypeScript or Vite errors, and `/` renders "Hello World" centered both axes on a light background.
11. The subtitle is visibly lighter/smaller than the heading; spacing looks balanced at 375px, 768px, and 1440px widths with no horizontal scrolling.
12. No additional routes, links, buttons, state, or data fetching exist anywhere in `src/`.
13. `src/styles/global.css` contains the Tailwind import as its first line and is imported exactly once, in `src/main.tsx`.
14. No inline style objects and no CSS files other than `src/styles/global.css`.
